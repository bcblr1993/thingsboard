# 金仓适配 AI 使用说明

> 分支：`feature/kingbase-V008R006C009B0014-pg-oracle`　技术细节见 `docs/kingbase-pg-oracle.md`

## 二、具体做法（5 步）

| 步骤 | 人做什么 | AI 做什么 | 产出 |
|---|---|---|---|
| **1. 环境准备** | 确认客户使用的数据库版本：V008R006C009B0014 | 在机器上安装对应版本的金仓，分别初始化 pg、oracle 两种兼容模式的库 | 两套可用的金仓测试库 |
| **2. 摸底与定位** | 确认摸底范围和判定标准 | 把 dao 层全部 950 个测试用例分别跑在 PostgreSQL 和两种金仓模式上，逐项比对失败清单；从 oracle 模式的 2740 条报错中归纳出唯一根因 | 结论：pg 模式无差异；oracle 模式 448 个用例失败，全部由同一个原因引起（金仓 oracle 模式只自带两个参数的 `concat`，三个参数的调用全部报错） |
| **3. 适配开发** | 审核方案，确定"不改业务代码"的原则 | 编写 3 行 SQL 补丁；在安装程序中加入"自动识别金仓模式 → 检查权限 → 打补丁 → 复验"逻辑；补 9 个单元测试；测试配置支持指向外部数据库 | 代码提交 `bf0e00b1b` |
| **4. 开发后验证与修复** | 评审测试结果 | 全量用例在 PostgreSQL / 金仓 pg / 金仓 oracle 三套环境回归；用原始代码在同一 PostgreSQL 上做对照，确认零影响；补丁重复执行验证幂等 | 三套环境失败清单逐项一致，oracle 模式补丁后 concat 报错 0 条 |
| **5. 71 环境闭环实跑** | 提供 71 环境，确认结果 | 在 10.8.8.71 上实际部署运行，发现问题当场修复；编写 docker-compose 一键部署脚本，确认镜像与宿主机金仓版本一致 | 首次部署与重复部署均成功；代码提交 `289eee7de`；部署文档 `docs/kingbase-pg-oracle.md` |

**分工原则：人负责定版本、定方向、做判断；AI 负责装环境、跑测试、查原因、写代码、写文档。**

## 三、为什么能快 3 倍

1. **环境搭建快**：金仓安装、两种模式初始化、建库授权由 AI 直接在机器上完成，不用人查手册反复试。
2. **摸底快**：950 个用例 × 3 套环境的结果比对，人工要逐条看；AI 自动跑、自动比对。
3. **定位快**：2740 条报错人工要一条条排查；AI 直接归纳出是同一个根因，避免了大面积改代码。
4. **方案更省**：找准根因后只需 3 行 SQL 补丁，不用改业务代码，开发量和回归风险都大幅降低。
5. **验证闭环快**：回归、对照、71 实跑、发现问题、修复、再验证，全程由 AI 执行，人只看结果。

## 四、后续

- 金仓 mysql 兼容模式本期未做：存在 `||` 语义不同、强制大小写不敏感等问题，需要改查询和方言，且涉及业务语义，需业务确认后再评估。
- 同样的方法可以复用到其他国产数据库（如达梦、海量等）的适配。
